# Hermes UI v2: shared brief for workers (read fully)

The user asked for: palette taken from a pixel-art tile (navy, gold, amber, cream, teal, green, magenta -> indigo -> aqua), a far less cluttered UI, ONE main goal per screen, BIG TITLES IN THE BACKGROUND with BIG ILLUSTRATIONS taking most of the whitespace, expandable sidebars for the necessary-but-secondary information, premium transitions that START FAST AND END SLOW (ease-out: `var(--ease)` = cubic-bezier(.16,1,.3,1)), and responsive buttons.

Direction (taste-skill "colour chapters"): every space is a flat colour field ("stage") with a giant ghost title behind, a big pixel mosaic illustration, one short sentence, one primary action and a few doorways. Anything denser opens in a right-hand drawer (the "workbench") that slides in. The thread (chat) uses the theme surfaces (cream paper in light, deep navy in dark) and is just as quiet.

Rules: tokens only (`css/base.css`): `--ground --surface --raised --text --muted --accent --accent-ink --live --gold --navy ...` and chapter colours `--ch-inbox/--on-inbox` etc. No smooth gradients, no glows, no resting shadows (only floating things: drawers, menus), no emoji, no icon-in-coloured-square, no tiny uppercase labels, no eyebrows above headings, no thin decorative rules. Sentence case. One typeface (Plus Jakarta Sans via `var(--font)`), mono only for real code. Buttons: base.css `.btn` (`.primary` gold in dark / navy in light, `.big`, `.ghost`, `.line` inside stages). Every transition `var(--t-mid) var(--ease)` or `var(--t-slow) var(--ease)`; never `linear` or default `ease`. Reduced-motion is already handled globally.
Kit (read `js/stage.js`, `js/mosaic.js`, `css/stage.css`, `js/ui.js`): `H.defineStage(def)` / `H.stage(def, ctx)` builds a stage; `H.mosaic({glyph, seed, state})` builds the illustration; `H.drawer(opts)`; `H.work.<name>` = dense workbench module (existing `H.views.<name>` modules, registered into `H.work` by your file before you override the view). Mosaic glyph names live in `H.glyphs` (js/glyphs.js).
Never edit files you do not own (listed in your brief). Do not start servers. Verify with `node --check <file>`.
